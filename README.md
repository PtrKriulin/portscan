# portscan

Пакет TCP-сканирования портов (TCP Connect).

Пакет не зависит от CLI, HTTP-фреймворков, баз данных и брокеров сообщений —
только стандартная библиотека Go. Предназначен для встраивания в другие
Go-приложения.

## 1. Использование пакета

```go
import "github.com/PtrKriulin/portscan"

scanner, err := portscan.New(
    portscan.WithConcurrency(100),
    portscan.WithConnectTimeout(500*time.Millisecond),
)
if err != nil {
    return err
}

results, err := scanner.Scan(
    ctx,
    []string{"192.168.1.10", "example.com", "10.0.0.0/29", "fd00::/126"},
    portscan.Range(1, 1000),
)
if err != nil {
    return err
}

for result := range results {
    fmt.Printf("%s:%d %s\n", result.Host, result.Port, result.State)
}
```

Сборка и тесты: `go test -race ./...` (Go 1.25.5, только стандартная библиотека).

## 2. Публичный API

| Сущность | Назначение |
| :--- | :--- |
| `New(opts ...Option) (*Scanner, error)` | Создание сканера. Некорректные опции (конкурентность ≤ 0, таймаут ≤ 0) дают ошибку. |
| `WithConcurrency(n int) Option` | Максимум одновременно выполняемых подключений на весь сканер (общий лимит для всех вызовов `Scan`). По умолчанию 100. |
| `WithConnectTimeout(d time.Duration) Option` | Таймаут одной попытки подключения. По умолчанию 1 с. |
| `(*Scanner).Scan(ctx, hosts, specs ...PortSpec) (<-chan Result, error)` | Скан: валидация и разрешение хостов — синхронно, проверки — конкурентно. Канал закрывается один раз после завершения всех проверок или отмены контекста. Scanner не хранит изменяемого состояния: один экземпляр можно использовать многократно, в том числе из нескольких горутин. |
| `Range(from, to int) PortSpec` | Диапазон портов. |
| `List(ports ...int) PortSpec` | Список отдельных портов. |
| `State` + `StateOpen, StateClosed, StateTimeout, StateUnreachable, StateCanceled, StateError` | Итог проверки. Классификация — по типам ошибок (`errors.Is`/`errors.As`), не по тексту. |
| `Result` | `{Host string; IP net.IP; Port uint16; State State; Duration time.Duration; Err error}`. |

Ошибки валидации (пустые хосты/порты, порт вне [1, 65535], обратный диапазон)
возвращаются из `Scan` как `error` до любой сетевой активности. Сбой
разрешения отдельного хоста сканирование не прерывает: он даёт один
`Result` с `State: StateError` и заполненным `Err`.

## 3. Поведение в граничных случаях

| Ситуация | Поведение |
| :--- | :--- |
| Пустой хост / пустой список хостов | Ошибка валидации до старта. |
| Некорректный адрес или ошибка разрешения DNS-имени (любая, кроме отмены контекста) | Один `Result` со `StateError`, остальные хосты сканируются. |
| Повторяющиеся хосты и порты | Дедупликация по паре (исходная строка хоста, адрес): повтор той же строки не сканируется второй раз; разные строки (литерал и CIDR, два DNS-имени), указывающие на один адрес, дают по собственному результату на каждую строку. |
| CIDR-нотация (`10.0.0.0/24`, IPv4 и IPv6) | Цель на каждый адрес диапазона, включая адрес сети и broadcast. Некорректный CIDR, биты хоста или более 65536 адресов в диапазоне (префикс уже `/16` для IPv4, `/112` для IPv6) — ошибка до старта. |
| DNS-имя с несколькими IP | Сканируется каждый адрес; `Result.Host` — исходная строка, `Result.IP` — конкретный адрес. |
| Порт 0, порт > 65535, обратный диапазон (1000–1) | Ошибка валидации до старта. |
| Отмена `ctx` | Новые задания не отправляются и не выполняются (проверка отмены до отправки и до подключения), in-flight подключения прерываются: итог `StateCanceled` доставляется по возможности (best effort — при заполненном буфере канала часть таких результатов может не уместиться), канал закрывается. Потребитель, переставший читать, не блокирует отмену. |
| Медленный потребитель | Канал результатов буферизован; воркеры приостановятся, ничего не теряется. |
| `ECONNRESET` (RST) | Трактуется как `closed`, как в nmap: RST на SYN на практике означает отказ порта. Возможный RST от промежуточного устройства неотличим от ответа хоста — это принципиальное ограничение TCP Connect. |

## 4. Ограничения

* Только TCP Connect: SYN/UDP-сканирование, raw sockets, определение ОС и обход фильтров не реализуются (и не входят в задачу).
* Firewall в режиме drop всегда даёт `timeout` — свойство полного TCP-подключения, а не сканера.
* Дефолтная конкурентность 100: сканирование — сетевая задача (I/O-bound), ограничена сокетами и таймаутами, а не числом ядер. При высокой конкурентности проверьте лимит файловых дескрипторов (`ulimit -n`).
* Лимит конкурентности общий на сканер: параллельные вызовы `Scan` на одном экземпляре совместно используют заданный `WithConcurrency`.
* Разрешение DNS-имён выполняется синхронно и последовательно до старта проверок: большой список из медленно резолвящихся имён задержит начало выдачи результатов. Адреса сканируются конкурентно уже после резолвинга.
* IPv6-адреса с зоной (`fe80::1%eth0`) не поддерживаются и дают `error`.
* Классификация `closed`/`unreachable`/`timeout` опирается на системные errno через `errors.As(syscall.Errno)`. Поведение проверено на Linux; на других ОС (Windows/macOS) коды ошибок сопоставляются со значениями `syscall.Errno` из stdlib, но соответствие не проверено — нераспознанные ошибки дают `error`.
